# ContextShare

Структурированная база знаний проекта для людей и ИИ. Проект объединяет обзор,
секции, ноды, типизированные связи и очередь заявок. Для веба и Android
сохраняются отдельные подтверждения, сборки и части одной заявки.

## Локальный режим

Локальный MCP работает через stdio. `--project` задаёт начальную рабочую копию
репозитория с файлом `.contextshare/project.json`.

```powershell
go build -o contextshare.exe .
codex mcp add contextshare-local -- C:/Tools/contextshare.exe local --project C:/Projects/my-worktree
```

Для задачи вызовите `list_worktrees`, затем `select_worktree` с абсолютным путём
рабочей копии. Используйте возвращённый `project_id` во всех следующих вызовах.
Каждая копия получает свой идентификатор. Выбор в одном чате сохраняет
независимость от выбора в другом.

Ответы содержат путь, ветку, commit и признак незакоммиченных изменений
в `workspace`. Эта информация также доступна клиентам в `_meta.workspace`.
Статус `current` относится к материалу внутри этой ревизии рабочей копии.
Для записи через MCP требуется идентификатор из `select_worktree`.

Источник данных — `README.md`, каталог `wiki_dir` из конфигурации проекта и
текстовые файлы `.contextshare/`.
В `project.json` указываются `version: 1`, `project`, `sections` с путями или
префиксами с завершающим `*` и `fallback_section`. `notes/*.json` хранят
самостоятельные ноды и подтверждения по платформам, `links.json` — типизированные
связи, `requests/*.json` — заявки. Новые заявки записываются атомарно и повтор
операции проверяется по `operation_id`. Подготовка и взятие части задачи требуют
`expected_version`. Разные worktree сходятся через Git.

Вспомогательная SQLite-база `contextshare-index-v1.sqlite` находится в Git
каталоге выбранного worktree. При изменении файлов обновляется поиск, локальные
пути и ссылки. Поиск показывает действующие материалы по умолчанию.
История доступна по фильтру `historical` или `all`.
В `project.json` можно задать `search_aliases` как группы синонимов из отдельных
слов, например `[["характеристики", "статы"]]`. Они нормализуются той же русской
морфологией, что и документы, и участвуют в ранжировании и выборе фрагмента.
Обзор и чтение работают без HTTP и PostgreSQL.

Вики читается через `get_wiki_document`, вложения через `get_wiki_attachment`.
`write_wiki_attachment` сохраняет JSON, CSV, PNG и WebP, проверяя версию
существующего вложения. Изображение можно взять из файла в текущем worktree.
`write_wiki_document` создаёт страницу или обновляет её по SHA-256 полного файла.
Можно передать новый `content` либо уникальный фрагмент `find` и его `replace`.
`delete_wiki_document` защищает оглавление и страницы с входящими ссылками.
`set_wiki_link` обновляет типизированные связи. `validate_wiki` запускает проверку
структуры и ссылок в проекте. Для скриптов доступны `local --project PATH wiki
get|write|validate`, команды чтения и записи принимают JSON в stdin.

CLI также принимает обычные флаги:

```powershell
contextshare local --project C:/Projects/my-worktree wiki get --path features/maps.md --start-line 20 --lines 40 --text
contextshare local --project C:/Projects/my-worktree wiki edit --path features/maps.md --find "Старый текст" --replace "Новый текст"
contextshare local --project C:/Projects/my-worktree wiki write --path features/new.md --file C:/Temp/new.md
contextshare local --project C:/Projects/my-worktree wiki get --help
```

Для полной замены существующей страницы `wiki write` требует
`--expected-sha256`. `wiki edit` читает текущую версию и заменяет единственное
совпадение с защитой от параллельной правки. JSON-ввод доступен для скриптов.

## Облачный запуск

Нужен Go 1.26+ и PostgreSQL. Перед запуском задайте `DB_URL`, `DB_USER` и
`DB_PASSWORD`. Поддерживается и формат `jdbc:postgresql://…` для `DB_URL`.
Адрес по умолчанию — `http://127.0.0.1:8080`.

```sh
go run .
```

`GET /healthz` проверяет доступность БД и отдаёт ревизию сборки.
Приложение создаёт таблицы в схеме `contextshare`; тестовую схему задаёт
`CONTEXTSHARE_DB_SCHEMA`. Для первого аккаунта оператор передаёт SHA-256
одноразового приглашения через `CONTEXTSHARE_INVITE_SHA256`. Пользователь
вводит исходный код на `/register`. Файл `CONTEXTSHARE_SEED_FILE`, если задан,
импортируется в проект первого владельца в одной транзакции с регистрацией.
Владелец может выдавать отдельные приглашения редакторам и читателям.

## MCP

- `/mcp` обслуживает Streamable HTTP. Список операций проекта доступен
  только после входа.
- В ChatGPT добавьте URL `https://<адрес>/mcp` как пользовательский сервер
  с OAuth. При согласии выберите один проект и разрешённые операции.
  Используется Authorization Code с PKCE S256 и динамической регистрацией
  поддерживаемых клиентов.
- В клиенте с Bearer-аутентификацией создайте ключ в разделе «Доступ».
  Ключ показывается один раз, ограничен проектом и правами, действует 30 дней.
  OAuth-подключения и ключи отзываются в том же разделе.
- Команда `get_usage_guide` возвращает [правила работы с данными](docs/mcp-guide.md).
  Чтение и добавление во входящие разделены; подготовка к работе происходит
  в вебе. Взять конкретную часть можно с отдельным правом.

## Выпуск и проверка

`deploy/run.py` получает значения БД с ВМ через IAM и Lockbox и запускает
сервис без записи паролей в файл. Публичный PostgreSQL подключается через
`CONTEXTSHARE_DB_PUBLIC=1` и `CONTEXTSHARE_DB_CA` с проверкой имени хоста.
`deploy/activate.sh` принимает проверенный пакет, ревизию, HTTPS-адрес и
ожидаемый ID ВМ. Требуются заранее подготовленные Nginx и доверенный сертификат.
Перед отправкой оператор формирует `SHA256SUMS`, `runtime.env` и приватный
`pilot.json` рядом с бинарником и служебными файлами. Настоящие значения
секретов и пилотные данные хранятся вне Git.

`go test ./...` проверяет шаблоны и ограничения OAuth. Интеграционная проверка
доступна при `CONTEXTSHARE_RUN_INTEGRATION=1` и схеме вида
`ctx_test_<12 hex-символов>`. Она создаёт и удаляет только свою тестовую схему
и проверяет регистрацию, доступ, поиск, очередь, перенос нод и OAuth.
