# ContextShare

Структурированная база знаний проекта для людей и ИИ. Проект объединяет обзор,
секции, ноды, типизированные связи и очередь заявок. Для веба и Android
сохраняются отдельные подтверждения, сборки и части одной заявки.

## Запуск

Нужен Go 1.26+ и PostgreSQL. Перед запуском задайте `DB_URL`, `DB_USER` и
`DB_PASSWORD`. Поддерживается и формат `jdbc:postgresql://…` для `DB_URL`.
Адрес по умолчанию — `http://127.0.0.1:8080`.

```sh
go run .
```

`GET /healthz` проверяет доступность БД и отдаёт ревизию сборки.
Приложение создаёт таблицы в схеме `contextshare`; тестовую схему задаёт
`CONTEXTSHARE_DB_SCHEMA`. Для первого аккаунта оператор передаёт SHA-256
одноразового приглашения через `CONTEXTSHARE_INVITE_SHA256`. Пользователь
вводит исходный код на `/register`. Файл `CONTEXTSHARE_SEED_FILE`, если задан,
импортируется в проект первого владельца в одной транзакции с регистрацией.
Владелец может выдавать отдельные приглашения редакторам и читателям.

## MCP

- `/mcp` обслуживает Streamable HTTP. Список операций проекта доступен
  только после входа.
- В ChatGPT добавьте URL `https://<адрес>/mcp` как пользовательский сервер
  с OAuth. При согласии выберите один проект и разрешённые операции.
  Используется Authorization Code с PKCE S256 и динамической регистрацией
  поддерживаемых клиентов.
- В клиенте с Bearer-аутентификацией создайте ключ в разделе «Доступ».
  Ключ показывается один раз, ограничен проектом и правами, действует 30 дней.
  OAuth-подключения и ключи отзываются в том же разделе.
- Команда `get_usage_guide` возвращает [правила работы с данными](docs/mcp-guide.md).
  Чтение и добавление во входящие разделены; подготовка к работе происходит
  в вебе. Взять конкретную часть можно с отдельным правом.

## Выпуск и проверка

`deploy/run.py` получает значения БД с ВМ через IAM и Lockbox и запускает
сервис без записи паролей в файл. Публичный PostgreSQL подключается через
`CONTEXTSHARE_DB_PUBLIC=1` и `CONTEXTSHARE_DB_CA` с проверкой имени хоста.
`deploy/activate.sh` принимает проверенный пакет, ревизию, HTTPS-адрес и
ожидаемый ID ВМ. Требуются заранее подготовленные Nginx и доверенный сертификат.
Перед отправкой оператор формирует `SHA256SUMS`, `runtime.env` и приватный
`pilot.json` рядом с бинарником и служебными файлами. Настоящие значения
секретов и пилотные данные хранятся вне Git.

`go test ./...` проверяет шаблоны и ограничения OAuth. Интеграционная проверка
доступна при `CONTEXTSHARE_RUN_INTEGRATION=1` и схеме вида
`ctx_test_<12 hex-символов>`. Она создаёт и удаляет только свою тестовую схему
и проверяет регистрацию, доступ, поиск, очередь, перенос нод и OAuth.
